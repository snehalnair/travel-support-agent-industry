# infra/tofu — Kubernetes cluster skeleton (OpenTofu)

Infrastructure-as-code for the project's Kubernetes golden path (ADR-0001).
**This module is validated, not applied, in Phase 0.** It defines a local
[kind](https://kind.sigs.k8s.io/) cluster — the OSS target for the canary /
rollback demo — written so the cloud swap-in is a single-file change.

## Status

| | |
|---|---|
| Phase 0.11 | author + `tofu validate` (this step) — **no cluster created** |
| Phase 4.4  | `tofu apply` — kind cluster stood up for the Argo Rollouts canary |

`tofu validate` only type-checks the config and resolves the provider; it never
contacts Docker or creates infrastructure. That's why this lands in Phase 0
(scaffold) while the actual `apply` waits for Phase 4 (deploy).

## Why OpenTofu (not Terraform)

Terraform relicensed to the BSL (source-available, non-OSS) at v1.6. OpenTofu is
the Linux Foundation OSS fork and a drop-in CLI. Choosing it keeps the stack
zero-lock-in, consistent with kind→AKS, Postgres→Cloud SQL, and the LiteLLM
provider swap. (ADR-0004 records this once written.)

## Why kind locally

kind runs a real Kubernetes API server in Docker — the same control plane Helm
and Argo Rollouts talk to in cloud. It costs $0, comes up in seconds, and is
disposable, so the deploy mechanics (canary, health probes, < 5 min rollback)
are exercised for real without a cloud bill. AKS is the documented production
target, not a different paradigm.

## Cloud swap-in (AKS)

The module exposes one seam: it emits a `kubeconfig_path` that everything
downstream consumes. To target Azure instead of a laptop:

1. Swap the provider in `versions.tf` (`tehcyx/kind` → `hashicorp/azurerm`).
2. Replace `kind_cluster.this` in `main.tf` with `azurerm_kubernetes_cluster`.
3. Re-point the `kubeconfig_path` / `endpoint` outputs at the AKS attributes.

Helm releases and Rollouts manifests don't change — they target the kubeconfig,
not the provider. That's the point of isolating the cluster in this module.

## Provider pinning

`versions.tf` sets a floor (`>= 0.2.0`). The real pin is `.terraform.lock.hcl`,
generated by `tofu init` and committed: it records the exact resolved version and
per-platform checksums, so every machine and CI run gets an identical provider.
Before the Phase 4 `apply`, pin `kubernetes_version` to a `kindest/node` image
digest as well.

## Commands

```bash
tofu init       # downloads the kind provider, writes .terraform.lock.hcl
tofu validate   # type-checks the config — no infrastructure touched
tofu fmt        # canonical formatting

# Phase 4.4 only — needs Docker + the kind binary:
# tofu apply
# tofu destroy
```

## Variables

| Variable | Default | Purpose |
|---|---|---|
| `cluster_name` | `tsa-dev` | Cluster name; kubeconfig context is `kind-<name>`. |
| `kubernetes_version` | `v1.31.0` | `kindest/node` image tag. |
| `worker_count` | `1` | Worker nodes beyond the single control-plane node. |
